# Карта локальных проблем (Ханты-Мансийск)

«Карта локальных проблем» — это общественная веб-платформа, позволяющая жителям г. Ханты-Мансийска оперативно сообщать о проблемах городской среды (ямы, мусор, неисправное освещение) с привязкой к интерактивной карте. Проект создаёт цифровой мост между населением и администрацией, повышая прозрачность взаимодействия и эффективность решения локальных задач.
Реализовано на Django + PostGIS + MapLibre GL. Выполнено в рамках «ОБЩЕСТВЕННЫЙ ПРОЕКТ «ОБУЧЕНИЕ СЛУЖЕНИЕМ».

---

## Запуск

### Требования
- Docker и Docker Compose  
- Python 3.11+ (опционально)  
- Зависимости: `Django==5.2.6`, `GDAL==3.10.3`, `psycopg2-binary==2.9.9`

### Пошагово

1. **Подготовьте окружение**  
   ```bash
   cp .env.example .env
   ```
   Заполните .env.
   SECRET_KEY сгенерируйте через python и вставьте в .env:
   ```bash
   python -c "import secrets; print(secrets.token_urlsafe(50))"
   ```

2. **Запустите контейнеры**  
   ```bash
   docker-compose up --build
   ```

3. **Примените миграции**  
   ```bash
   docker-compose exec web python manage.py makemigrations
   docker-compose exec web python manage.py migrate
   ```

4. **(Опционально) Создайте суперпользователя**  
   ```bash
   docker-compose exec web python manage.py createsuperuser
   ```
   Нужно только для доступа к `/admin/`.

5. **Проверьте**  
   - `http://localhost:8000` — главная  
   - `http://localhost:8000/issues/map/` — карта  
   - `http://localhost:8000/admin/` — админка (если создан суперпользователь)

## Запуск тестов

Проект включает полное покрытие unit- и интеграционных тестов (38+ тестов), включая:
- Регистрацию и верификацию email через UUID-токен  
- RBAC: `citizen` и `official`  
- Работу с `PointField`, `IssuePhoto`, `Vote`  
- Геокодирование (моки вместо внешних API)  
- API-эндпоинты (`/vote/`, `/geojson/`, `/api/geocode/`)

Все тесты изолированы, не совершают внешних HTTP-запросов и предназначены для запуска внутри Docker-контейнера.

#### 1. Подготовка тестовой базы данных

Тесты используют отдельную БД, чтобы не затирать dev-данные.

- Создайте тестовую БД (контейнер `db` должен быть запущен), вместо DB_USER вставьте свой DB_USER, указанный в .env
```bash
docker compose exec db createdb -U DB_USER map_of_local_issues_test
```
- Примените миграции к тестовой БД
```bash
docker compose run --rm -e DB_NAME=map_of_local_issues_test web python manage.py migrate
```

#### 2. Запуск тестов
Запуск всех тестов с сохранением БД между прогонами

```bash
docker compose run --rm -e DEBUG=True -e DB_NAME=map_of_local_issues_test web python manage.py test tests --keepdb --verbosity=2
```

## Руководство пользователя

### Для граждан

#### Регистрация
1. На главной странице в правом верхнем углу нажмите **«Регистрация»**.  
2. Заполните поля:
   - Имя*, Фамилия*  
   - Отчество (необязательно)  
   - Электронная почта*  
   - Телефон (необязательно)  
   - Роль* → выберите **«Гражданин»**  
   - Пароль* → не менее 12 символов (должен содержать буквы разного регистра, цифры и спецсимволы)  
   - Подтверждение пароля*  
3. Нажмите **«Создать аккаунт»**.  
4. Проверьте почту и перейдите по ссылке подтверждения.  
5. После подтверждения войдите в систему через **«Вход»**.

#### Создание обращения
1. Перейдите на **«Карту»** (`/issues/map/`).  
2. Укажите место проблемы:
   - Введите адрес в поле поиска (подсказки появятся автоматически), **или**  
   - Кликните по карте — появится синяя метка и кнопка **«Сообщить о проблеме здесь»** в правом верхнем углу.  
3. Нажмите эту кнопку.  
4. В открывшейся форме укажите:
   - Заголовок*  
   - Описание*  
   - Категория* (например, «Дороги», «Освещение»)  
   - Фотографии (до 5 файлов, JPG/PNG, до 5 МБ каждый)  
5. Нажмите **«Отправить»**.  
6. Обращение получит статус **«Открыто»**, затем **«В работе»** (когда его возьмёт должностное лицо), и, наконец, **«Решено»**.

#### Взаимодействие с обращениями
- **Голосование**: под деталями обращения — кнопки 👍 / 👎.  
  Голос можно отменить повторным нажатием.  
- **Комментирование**: внизу карточки — форма для комментария (доступна всем авторизованным).  
- **Фильтрация**: на карте — панель фильтров (категория, статус, поиск, сортировка).

---

### Для должностных лиц

#### Вход и управление
- Роль **«Официальное лицо»** назначается при регистрации (или администратором в `/admin/`).  
- После входа доступны:
  - Изменение статуса обращения («В работе» → «Решено»)  
  - Удаление обращений (только своих или с подтверждением)  
- Все действия логируются через Django messages.

## Внешние сервисы и ограничения

Проект использует **публичный Nominatim OpenStreetMap** (`nominatim.openstreetmap.org`) через проксирующие Django-представления:
- `/issues/api/geocode/`  
- `/issues/api/reverse-geocode/`  
- `/issues/api/search-address/`

Соблюдены все условия [Acceptable Use Policy](https://operations.osmfoundation.org/policies/nominatim/):
- Запросы инициируются только конечным пользователем (поиск/клик),  
- Реализовано кэширование,  
- Указан корректный `User-Agent` с email администратора,  
- Запрещены периодические/автоматические запросы.

> **Важно**: при росте нагрузки рекомендуется развёртывание локального Photon или использование коммерческого геокодера.

## Архитектура

Проект построен по принципу явного разделения ответственности. Все компоненты изолированы и легко тестируемы.

### Модельный слой
- **`CustomUser`**  
  `email` — основной идентификатор. Поддержка ФИО (включая отчество), роли (`citizen`/`official`), телефона, департамента. Верификация email через `UUID4`-токен.
- **`Issue`**  
  Геометрия хранится как `PointField(srid=4326)`. Инвариант: `resolved_at` устанавливается один раз — при первом переходе в `STATUS_RESOLVED`.  
  Свойство `rating` оптимизировано: при наличии аннотации `_rating` — не делает запрос к БД.
- **`Vote`**  
  Уникальность `(user, issue)`. `vote=0` реализуется как `delete()`. Голосовать могут только граждане.
- **`IssuePhoto`**  
  Валидация: расширения `jpg/jpeg/png`, размер ≤ 5 МБ на файл, максимум 5 файлов.

### Логический слой
- Роль проверяется явно в коде — без middleware.
- `create_issue`: приоритет — ручные координаты (из клика по карте), затем геокодирование адреса.
- `vote_issue`: идемпотентно. Возвращает `rating` и `user_vote` в JSON.
- `map_view` и `get_issues_geojson` используют единую логику фильтрации.

### Геокодирование (`issues/modules/geocoding.py`)
- Единственный внешний API: **Nominatim OpenStreetMap** (`nominatim.openstreetmap.org`).
- Соблюдение ToS:
  - Уникальный `User-Agent` с email администратора (`ss@yandex.ru`)
  - `email` в reverse-запросах
  - Задержка `0.5s` между reverse-вызовами
  - Кэширование результатов на 2 часа
  - `viewbox` + `bounded=1` для ХМАО
  - Таймауты до 8 секунд
- Фолбэк: при промахе — возврат `"Ханты-Мансийск, ХМАО"` или координат.
- Все запросы браузера идут **только во внутренние Django API**, а не напрямую в Nominatim.

### Представление
- Шаблоны: иерархия через `base.html`, частичные рендеры для AJAX.
- Фронтенд: `vanilla JS`, MapLibre GL, поддержка `X-Requested-With: XMLHttpRequest`.
- Безопасность: `escapejs` для данных в попапах, `CSRF`-токен в `fetch`.

### Инфраструктура
- База: PostgreSQL 15 + PostGIS 3.4 (`django.contrib.gis.db.backends.postgis`)
- Кэширование: `LocMemCache` 
- Логирование:  
  - `geocoding` → `INFO`  
  - `django.request` → `INFO` (4xx/5xx в консоль)  
  - `django` → `ERROR` → `error.log`
- Безопасность: пароли ≥ 12 символов, `SECURE_*` флаги в prod, `CSRF_COOKIE_SECURE`.
